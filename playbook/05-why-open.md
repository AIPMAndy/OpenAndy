# 为什么把这些免费放出来

> `[公开自述]` 文章第七节写到：2026 年开始做更多开源项目，把研究 AI、做产品、求职、创业、赚钱的方法整理出来放到 GitHub 上。"很多人不理解，为什么这些东西不全部拿去收费？"

## 作者给的理由（S1）

> "我小时候没有多少资源，很多东西只能靠自己一点一点研究。如果今天的普通人，可以通过我公开的一份教程、一个工具，少花几千块钱，少走几个月弯路，我觉得这件事就值得做。"

同时，他没有把这件事说成纯公益：

> "当然，我还要赚钱。我有家庭，有孩子，有公司要经营，也有很多没有实现的理想。"

这两句必须一起读。按公理 3（对立统一），开源与商业化在这里不是对立面，而是**在同一套约束下并存**：一部分知识免费公开，一部分服务继续收费，两者服务不同的人群与不同的问题。

## 这个仓库如何落实

`[本仓库整理]` 把"免费"落成可核对的约束，而不是一句姿态：

| 约束 | 具体做法 |
|---|---|
| 全量可读 | 正文全部是仓库里的 Markdown，无需登录、无需加微信、无需加群 |
| 不设转化漏斗 | 没有付费墙、没有"完整版请私信"、没有课程链接 |
| 可被 AI 读取 | 提供 [`llms.txt`](../llms.txt)、[`llms-full.txt`](../llms-full.txt)、[`data/index.json`](../data/index.json) 与 [AGENTS.md](../AGENTS.md) |
| 零门槛运行 | CLI 只用 Python 标准库，不联网、不要 API Key |
| 可离线复制 | 内容许可允许署名非商业地自由复制与分发 |
| 可核对 | 每个事实标来源，口径冲突明写不合并，数字全部标"自述、未审计" |
| 不夸大 | 不承诺收益、不把案例包装成可复制结果 |

## 为什么"可核对"比"内容多"更重要

`[本仓库整理]` 按公理 2（还原）与公理 6（因果边界）：一份不能核对的经验，读者只能选择"全信"或"全不信"。做了三件事之后，读者可以自己判断：

1. **分级**：`[公开自述]` / `[工作原则]` / `[本仓库整理]`，见 [SOURCES.md](../SOURCES.md)。
2. **留白**：材料冲突处标 `[存疑]`，没有证据的格子就空着（见 [STORY.md](../STORY.md) 第 6 节）。
3. **给代价**：每个阶段都写"付出"，不把路径画成只涨不跌的曲线。

这也是本仓库不生成"人生建议"的原因。**它提供的是可检索的原始材料与判断规则，结论由读者自己下。**

## 什么不放在这里

- 客户姓名、公司、岗位、合同金额与可识别案例细节；
- 未公开的履历、融资条款、家庭身份信息、联系方式；
- 收益承诺、成功学叙事、"照做就能复制"的暗示；
- 任何需要付费才能看的内容。

## 维护是有成本的（公理 1）

`[本仓库整理]` 开源不是一次性动作：来源会变化，索引会漂移，链接会失效。因此仓库里放了三样东西，而不是只放文章：

- `openandy.py check`：校验索引路径、来源 ID、相对链接与敏感信息模式；
- `openandy.py build`：从 Markdown 重新生成 `llms-full.txt`，避免两份正文不同步；
- `tests/test_openandy.py`：对上述行为做断言，而不只是检查"文件存在"。

对应工程方法的第 5 步：先删、再简化、最后才自动化。自动化在这里只服务于**防止内容腐烂**，不用于生产更多内容。

## 参与方式

欢迎补充有出处的勘误、把某条方法用到自己场景后的复盘（无论成败）、以及翻译。规则见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
